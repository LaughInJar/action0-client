# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`action0-client` is a Python library for building backend-agnostic, fully typed HTTP API clients: the same client and operation classes run synchronously, on asyncio or on Twisted — the plugged-in backend decides, and the static types follow it. It ships the `action0.client` package (`action0` is a PEP 420 namespace package) from a `src/` layout, is built with hatchling, and uses `uv` for environment/dependency management. Runtime dependencies are `action0-req` and `action0-url` (from PyPI); the HTTP libraries (`requests`, `httpx`, `httpx2`, `aiohttp`, `urllib3`, `twisted[tls]`) are optional extras and dev-group dependencies; the `urllib` and thread-pool backends are stdlib-only.

## Rules

- **Never commit without asking.** Also never push, tag, or publish on your own.
- **Branches + PRs.** All changes go through feature branches and GitHub pull requests that Simon reviews and merges — never commit to `main` directly. (Only the initial implementation was built directly on `main`; that phase is over.)
- **Discuss first.** Always present the plan and the intended edits and get agreement before changing files.
- Every code change comes with: tests, docstrings, inline comments where the code isn't self-explanatory, and updated usage examples in `README.md` and the Sphinx docs (the guide pages in `docs/usage/`).
- Before considering work done, run ruff, mypy, pyright, ty, and pytest (commands below) and fix what they report.
- Supported Python versions: 3.11 up to the latest release. Don't use syntax or stdlib features introduced after 3.11, and don't rely on behavior removed in newer versions.

## Commands

`uv run` syncs the environment automatically (the dev dependency group, which includes all optional backend libraries, is installed by default), so no separate install step is needed.

```sh
uv run pytest                                        # all tests
uv run pytest tests/action0/client/test_client.py    # one file
uv run pytest tests/action0/client/test_init.py::PackageTestCase::test_version  # one test

uv run ruff check      # lint (add --fix to autofix)
uv run ruff format     # format
uv run mypy            # type-check (strict; files are configured in pyproject.toml)
uv run pyright         # type-check
uv run ty check        # type-check

uv run python examples/petstore.py   # the runnable example (network-free demo)

uv run --group docs sphinx-build -W --keep-going -b html docs docs/_build/html  # build docs

uv build               # build sdist + wheel into dist/
```

`pytest` also runs the `>>>` examples in the docstrings as doctests (`--doctest-modules` over `src/`), so docstring examples must produce their shown output exactly.

## Architecture

The layout under `src/action0/client/`:

- `backend.py` — the heart of the design. ONE structural protocol, `Backend[SendResultT_co]`, generic over what `send()` wraps the `Response` in (`Response` / `Awaitable[Response]` / `Deferred[Response]` / `Future[Response]` / anything else — `SyncBackend`/`AsyncBackend`/`DeferredBackend`/`FuturesBackend` are mere `TypeAlias`es of those instantiations). The second protocol method `map(result, fn)` applies a function *inside* the wrapper (plain call / await / `addCallback`); it is the runtime composition hook for `APIClient` and is typed loosely (`Any`) on the protocol — "the same wrapper around a different value type" is inexpressible for arbitrary wrappers (Python has no higher-kinded types); implementations type their `map` precisely. Also defines the two public TypeVars: `SendResultT_co` (what `Client` is generic over) and `BackendT_co` (bound `Backend[Any]`, what `APIClient` is generic over). Base classes `BaseSyncBackend`/`BaseAsyncBackend`/`BaseDeferredBackend` implement `send` as a template around an abstract `_send` (raw I/O only) adding `Hook` instrumentation and `translate_error`. `BaseDeferredBackend` imports twisted only lazily inside `send`, so the module (and the stub subclass) is importable without twisted.
- `client.py` — `Client[SendResultT_co]`: fully execution-model-agnostic, `send()` returns exactly what the backend's `send` returns — derived from the backend, works for wrapper types the library has never heard of, zero overloads, no twisted imports. Trade-off: `client.backend` is typed as the `Backend` protocol, not the concrete class (users keep their own reference for `close()` etc.).
- `operation.py` — `Operation[R_co]`: `@dataclass_transform` base class; `__init_subclass__` applies `dataclasses.dataclass(kw_only=True)` and validates (reserved names — DERIVED via `_reserved_names(cls)` from the public names of the library's own operation base classes in the MRO, so methods like `check`/`load` are covered and the list cannot lag; application base classes do not reserve anything; the public `reserved_field_names()` is for code generators; path placeholders ↔ `path_param()` fields; at most one body form). ClassVars `method`, `path` (template with `{name}` placeholders), `accept`, `default_location` (placement of specifier-less fields, default QUERY). `as_request(base_url)` renders the path template, serializes fields per location (`None` = omitted; enums → value, dates → ISO, bools → true/false, lists → repeated params) and assembles the JSON or form-urlencoded body (+ Content-Type if unset). `parse()` = `check()` (2xx or `APIError`) + abstract `load()`. `JsonOperation[R_co]` implements `load` via JSON decode + overridable `load_json` (default returns payload as-is, for `JsonOperation[Any]`). No `typing.get_type_hints` anywhere — field placement lives in `dataclasses.field(metadata=...)`, so user modules may freely use `from __future__ import annotations`.
- `fields.py` — the PEP 681 field specifiers `query()`, `header()`, `path_param()`, `json_field()`, `json_body()`, `form_field()`, `body()` producing `dataclasses.field(metadata={"action0-client": FieldSpec(...)})`. The wire-name parameter is called `name`, NOT `alias` — PEP 681 reserves `alias` for renaming the `__init__` parameter and ty actually implements that. `repr=False` keeps secrets out of operation reprs.
- `api.py` — `APIClient[BackendT_co]`: backend + `base_url` + default `headers`; pipeline is `prepare(operation.as_request(base_url))` → `backend.map(backend.send(request), operation.parse)` — runtime-agnostic. The typing facade cannot be: "the backend's wrapper around R" needs higher-kinded types, so `send` is `@overload`ed **on the self type** for the shipped models (`self: APIClient[Backend[Response]] -> R`, `...[Backend[Deferred[Response]]] -> Deferred[R]`, `...[Backend[Awaitable[Response]]] -> Awaitable[R]`, `...[Backend[Future[Response]]] -> Future[R]` — Deferred before Awaitable is load-bearing, a Deferred *is* awaitable) plus a final catch-all overload returning `Any`, so backends with other wrappers are usable, just untyped — the documented escape hatch for precise typing of a custom wrapper is subclassing `APIClient` and re-declaring `send()` (one cast + one pyright override suppression; see the guide's "Other execution models" and `BoxAPIClient` in `test_typing.py`). Covariance of `BackendT_co` makes `APIClient[RequestsBackend]` assignable to `APIClient[Backend[Response]]`, which resolves the overloads; `client.backend` keeps the concrete backend type. `prepare()` merges default headers (gaps only) and is the override point for signing/auth.
- `errors.py` — `ClientError` → `TransportError` (with `.request`; `TimeoutError` additionally subclasses the built-in `TimeoutError`) and `APIError` (with `.request`/`.response`) → `PayloadError` (acceptable status, unusable body; raised by `JsonOperation.load`; a class of its own so a retry policy can name it without retrying every unexpected status). Backends translate library exceptions via `translate_error`, chaining the original as `__cause__`.
- `hooks.py` — `Hook` (no-op base: `on_request` may replace the request, `on_response(request, response, elapsed)` may replace the response, `on_error` observes) and `LoggingHook` (logs via `repr()`, which redacts secrets).
- `options.py` — `RequestOptions`: the ONE mechanism for per-request choices. A frozen, keyword-only dataclass whose fields all default to `None` ("not decided here" — the backend's/policy's own setting applies), stored in `request.meta` under the single key `"action0-client"`. `apply(request)` merges field-wise into options already on the request (decided fields win), `RequestOptions.of(request)` reads (a shared empty instance when absent — no allocation on the hot path). `Operation.request_options` (ClassVar) applies one instance to every request in `as_request`; dynamic cases override `as_request`. Every new per-request or per-operation setting becomes a FIELD here, added together with the code that honours it — never a new `Operation` class attribute (see the reserved-names convention below).
- `wrapper.py` — the public base classes for backends wrapping another backend: `SyncBackendWrapper`/`AsyncBackendWrapper`/`DeferredBackendWrapper`. Each holds `inner` (typed as the `Backend` protocol of its execution model, deliberately not generic over the concrete inner type — TypeVar defaults need 3.13, and strict mypy would force every subclass to parameterize), a pass-through `send` that subclasses override (the async one is a coroutine function, so an awaited pre-send step like a rate limiter is a few lines — what a synchronous `Hook` cannot do), a precisely typed `map` that DELEGATES to the inner backend (one `cast`, because the protocol types `map` loosely) and `__repr__`. Wrappers have no hooks of their own. The retry and caching wrappers subclass these. Documented stacking order (pinned by `StackingOrderTestCase`): cache → retry → throttle → backend with hooks; hooks on the inner backend see every attempt, a cache hit never reaches it.
- `_parse.py` — how wrappers learn whether a response is USABLE, not just what status it has: `APIClient.send` wraps `operation.parse` in a `ParseOnce` (memo keyed by response identity — only the latest response is remembered), puts it on the request as `request.meta["action0-client.parse"]` and passes the same object to `backend.map`. Wrappers call `parse_failure(request, response)`; the final map step then reuses the outcome, so parsing runs exactly once per response (pinned by a test counting `load` calls). This is why there is still exactly ONE retry loop (in `retry.py`) and no loop in `APIClient`: attempts cannot multiply between layers, and `send`/`map` and the `APIClient.send` overloads are untouched. Wrappers must return the response object they got from the inner backend on the non-cached path, or the memo misses.
- `retry.py` — backend-agnostic retries as wrappers (retrying is send-again, so it cannot be a `Hook`): `RetryPolicy` (frozen dataclass: attempts/backoff/multiplier/max_backoff, transient statuses, `retry_errors=(TransportError,)`, idempotent-methods gate — `methods=None` allows all; full jitter by default with injectable `rng`, `Retry-After` honored — seconds and HTTP-date — capped at max_backoff) + `RetryingSyncBackend`/`RetryingAsyncBackend`/`RetryingDeferredBackend`, each preserving the inner backend's wrapper type so the client typing is untouched. Opt-in `retry_parse_errors` (default empty; `(PayloadError,)` for JSON decode failures) makes a response that passes the status check but fails `parse` retryable — checked via `_parse.parse_failure`, only while a retry is still possible. One attempt counter covers transport errors, statuses and parse failures. `applies_to` honours `RequestOptions.retry_safe`. Stacked retrying wrappers never multiply: the OUTERMOST claims the request (`request.meta["action0-client.retry"]`, released in `finally`/`addBoth`), inner ones pass through. A rejected response is closed (`close()`/`aclose()`, errors suppressed) before the wait. Exhausted attempts return the last response / raise the last error as-is — a retryable status then reaches `Operation.check`, which raises `APIError` with the response attached. Sync/async take injectable `sleep` (async default `asyncio.sleep`; pass `trio.sleep` on trio), deferred takes a `reactor` (lazy global default) and waits via `deferLater`.
- `caching.py` — explicit TTL response caching as wrappers (deliberately NOT RFC 9111 — no Cache-Control/validators): `CachePolicy` (ttl, cacheable methods {GET, HEAD} and statuses {200}, `max_body_size`; the sha256 key covers method + URL + `vary_headers` + — only for requests that have one, so bodyless keys never changed — a digest of the body. `vary_headers` are the ONLY headers in the key, so volatile ones never fragment the cache. Per request via `RequestOptions`: `cacheable` overrides the method gate both ways, `cache_key` replaces the computed key verbatim, `cache_ttl` → `ttl_for()`. Fail-safe in `should_lookup`: a request with a producer body is cached only under an explicit key. Producer response bodies — streamed or spooled — are never stored), the two-method `CacheStore` protocol (plus its awaitable twin `AsyncCacheStore`, accepted by the async wrapper only — sync store calls run inline, async ones are awaited via `inspect.isawaitable`), `MemoryCache` (thread-safe LRU + per-entry expiry, injectable clock) and `CachingSyncBackend`/`CachingAsyncBackend`/`CachingDeferredBackend`. Entries are stored WITHOUT their request (`_entry()`: `response.copy(request=None)`) so credentials and request `meta` never reach an external store — and so stored entries stay picklable. Hits are independent copies tied to the current request, with the body delivered in the request's body mode (`_body.deliver_bytes`/`adeliver_bytes`); on a hit the inner backend (and its hooks) is not involved.
- `backends/` — one module per HTTP stack. The response body mode is chosen PER REQUEST (`RequestOptions.body`: `BodyMode.PRELOAD`/`STREAM`/`SPOOL`); the `stream=` constructor argument of the non-twisted backends is only the backend's default. `_body.py` holds the shared logic: `body_mode(request, stream_default)`, and `deliver()`/`adeliver()` which turn a library's chunk iterator plus a `close` callback into the body — STREAM: `IterableBody`/`AsyncIterableBody` with the close callback (deterministic cleanup also for never-read bodies) and mid-stream errors passed through `translate_error`; SPOOL: a `SpooledBody` filled right there (`awrite()` on async backends: inline in memory, worker thread on disk), connection released in `finally`, half-filled spool closed on error. Preloading stays with each library. The `close` callback must be safe whether or not the body was read to its end (urllib3 distinguishes: release on completion, close otherwise). `UrllibBackend._chunks` raises `IncompleteRead` itself when the connection ends before Content-Length, because `http.client` only checks that for un-chunked reads. Twisted: PRELOAD via `readBody`, SPOOL via `_SpoolingProtocol` (in-memory writes inline; disk writes via `deferToThreadPool` with the transport paused, data arriving meanwhile batched into the next write; the `finished` Deferred's canceller — reached by `addTimeout` — aborts the connection; a reactor without `getThreadPool`, i.e. a test `Clock`, writes inline), STREAM raises `ValueError` before sending (see TODO.md). `_loops.py` solves the event-loop affinity of async clients: `PerLoop` keeps one object per running loop (dict keyed by `id(loop)` with a weakref for identity, a lock for the one-loop-per-thread case; the object is held by a started async generator whose `finally` closes it, so `loop.shutdown_asyncgens()` — run by `asyncio.run`/`Runner` — closes it inside its own loop; stale entries of loops closed the hard way are swept on next use; no asyncio loop, i.e. trio, means one shared object), `LoopBound` guards a single passed-in client and raises a clear `RuntimeError` on a foreign loop. `_httpx_family.py` is the ONE implementation behind the httpx and httpx2 backends: generic over the client class, the library module injected as `_lib` by the thin concrete classes; it imports neither library, which is what makes both modules importable with or without `httpx2.alias_httpx()`, and each backend translates only its own library's exceptions. Per module: `requests.py` (`RequestsBackend`; multi-value response headers via urllib3 raw headers, producer bodies as chunk iterators), `httpx.py` and `httpx2.py` (`HttpxBackend`/`AsyncHttpxBackend` and `Httpx2Backend`/`AsyncHttpx2Backend`, thin typed subclasses of the family classes; header lines and `multi_items()` keep multi-value fidelity; producer bodies stream sync/async; the async ones take `client=` (caller-owned, loop-bound) or `client_factory=` (one owned client per loop); httpx2 verifies TLS against the OS trust store — not overridden, documented), `aiohttp.py` (`AiohttpBackend`; owned sessions are per event loop via `PerLoop`, created inside the loop on first send — `session_factory=` configures them; a passed `session=` is loop-bound; timeouts arrive as `asyncio.TimeoutError`, checked before `ClientError`), `urllib3.py` (`Urllib3Backend` over `PoolManager.urlopen`; `retries=` passed through, timeouts unwrapped from `MaxRetryError`), `urllib.py` (`UrllibBackend`, stdlib-only; urllib's `HTTPError` for non-2xx is converted back into a `Response`; `_NoRedirects` handler for `follow_redirects=False`), `futures.py` (`ThreadPoolBackend`, stdlib-only; wraps any sync backend, `send` submits to a `ThreadPoolExecutor`, `map` chains via `add_done_callback` without occupying a worker; hooks belong on the wrapped backend), `twisted.py` (`TwistedBackend` over `Agent`/`RedirectAgent`, `readBody`, `_RequestBodyProducer` via `cooperate`, timeout via `addTimeout`; the global reactor is imported lazily in `__init__`, never at module import). All accept their library's native client/session/agent/pool (then never closed by the backend) or create their own (then closed by `close()`/`aclose()`).
- `testing/` — backend-independent mocking. `_router.py`: `MockRouter` (respx-like: `mock.get(url).respond(...)`, `route.mock(return_value=, side_effect=)`, `route.calls.last.request`, `assert_all_called`/`assert_all_mocked`; routes are tried in registration order, a private `_fallback` route serves the stubs' script). Activation is PROCESS-GLOBAL and explicit: `start()`/`__enter__` set `backend._mock` — the one slot the three base classes' `send` read (`mock = _mock; if mock is None: self._send(...) else mock._dispatch_{sync,async,deferred}(self, request)`), so hooks, `translate_error` and all wrappers still run; nothing else (no env var, no setting) may ever set it. Global rather than a contextvar on purpose: application code crosses threads and loops (`async_to_sync`, pools), where a context-local mock would silently not apply. Inactive cost: one global load + `is None`, ~5 ns per send (measured; stated in the guide). Unmatched requests raise `UnmockedRequestError(AssertionError)` and are recorded, so leaving the router fails even if the app swallowed it; `block_network=True` patches `socket.socket.connect`/`connect_ex` (`NetworkBlockedError` is also an `OSError` so libraries clean up). Answers are delivered in the request's body mode via `backends/_body` (`ChunkedBody` = chunks with an optional exception that breaks the body off: raised from `send` for PRELOAD/SPOOL, mid-iteration for STREAM; a backend with `_can_stream = False` — Twisted — gets its own `_refuse_stream()`). `_stubs.py`: `StubBackend`/`AsyncStubBackend`/`DeferredStubBackend` each own a private, never-activated router whose fallback is the script (canned `Response`s or responder callables; last response repeats; requests recorded; hooks run for real), exposed as `backend.router`; `deferred_result()` unwraps synchronously-fired Deferreds. `pytest_plugin.py`: the `action0_mock` fixture + marker, registered as a `pytest11` entry point — the ONLY module importing pytest, which is therefore not a dependency. `tests/.../test_mock_conformance.py` is the proof of backend independence: one suite run unchanged against all 13 shipped backends.

Conventions:

- The reserved operation field names are a CLOSED set, pinned by `test_the_reserved_names_are_a_closed_set`: do not add public attributes or methods to `Operation`/`JsonOperation`. Each one can break a user's operation that has a field of that name and forces a release of `action0-client-openapi`, which keeps its own copy of the list. New settings go into `RequestOptions`; new helpers are private or module-level functions.
- The version is single-sourced as `__version__` in `src/action0/client/__init__.py`; hatch extracts it with the regex in `[tool.hatch.version]`. Bump it only there.
- Releases: pushing a `vX.Y.Z` tag triggers `.github/workflows/release.yml`, which re-runs all checks, verifies the tag matches `__version__`, builds, and publishes to PyPI via trusted publishing (environment `pypi`). Never bump the version, tag, or publish on your own — releasing is the user's call.
- Tests mirror the `src/` layout under `tests/action0/client/` and are `unittest.TestCase` classes, executed via pytest. `tests/action0/client/test_typing.py` pins the static return-type promises with `typing.assert_type` — its `check_*` functions are analyzed by all three checkers but never executed. Its `Box`/`BoxBackend` (a wrapper type of its own) is the openness regression test: `Client.send` must type as `Box[Response]`, `APIClient.send` as `Any`, and `BoxAPIClient` pins the subclassing escape hatch.
- Zope interfaces (twisted's `IAgent`, `IResponse`, `IConsumer`, the global reactor) and static checkers don't mix: such values are typed `Any` with a comment, and `# type: ignore[...]` / `# ty: ignore[...]` are combined on one line where mypy and ty disagree.
- Ruff enforces one import per line (isort `force-single-line`), line length 99, `action0` as first-party.
- Docs live in `docs/` (Sphinx + Furo, MyST Markdown pages, autodoc for the API reference). Docstrings are Sphinx-reST (`:param:`, `:py:meth:` roles). CI builds them with `-W` on every run and deploys to GitHub Pages on pushes to `main`. Guide examples in `docs/usage/` (one page per topic, stitched together by `docs/usage/index.md`) show exact outputs in `#` comments — keep them truthful. `examples/petstore.py` is the complete worked example (type-checked in CI, runnable without network).
